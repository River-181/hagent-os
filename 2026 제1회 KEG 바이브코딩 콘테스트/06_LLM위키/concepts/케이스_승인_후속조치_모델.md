# 케이스 승인 후속조치 모델

## Summary First

HagentOS가 지향하는 운영 OS의 핵심 루프는 `chat -> answer`가 아니라 `case -> approval -> follow-up`이다. 즉, 사건을 케이스로 만들고, 사람 승인 지점을 노출하고, 실행 이후 후속조치와 기록까지 연결하는 구조가 제품의 본체다.

## 기본 루프

1. 문의, 민원, 예외 상황을 `case`로 접수한다.
2. 학생/학부모/강사/결제/상담 맥락을 조회한다.
3. AI가 초안, 대응안, 실행 후보를 정리한다.
4. 사람이 승인, 수정, 반려 중 하나를 결정한다.
5. 발송, 일정 생성, 문서 생성 같은 후속조치를 실행한다.
6. 결과와 재발 여부를 다시 케이스 이력에 남긴다.

## 왜 이 모델이 중요한가

- 교육 운영의 고통은 대개 “메시지를 쓰는 일”보다 “무슨 책임으로 어떤 예외를 처리했는가”에 있다.
- 승인 없는 자동화는 신뢰를 잃고, 승인만 있고 후속 기록이 없으면 같은 문제가 반복된다.
- 따라서 좋은 운영 제품은 답변형 챗봇보다 `승인주도 운영 시스템`에 가까워진다.

## Product Implication

- 민원 대응, 환불/할인, 강사 운영, 재등록 방어는 이 루프 위에서 설명해야 한다.
- board-first UI와 approval flow는 별도 기능이 아니라 이 루프를 드러내는 표면이다.
- 누적 맥락은 이 루프가 반복될수록 더 강해진다.
